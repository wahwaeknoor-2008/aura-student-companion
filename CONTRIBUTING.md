# Contributing to AURA

## Before starting
1. Pull the latest `main`.
2. Read the relevant document in `docs/`.
3. Check GitHub Issues to avoid duplicating work.

## Branch naming
Use descriptive branches, for example:
- `feature/mobile-dashboard`
- `feature/api-health`
- `fix/login-validation`
- `docs/update-architecture`

## Pull requests
- Keep each PR focused.
- Explain what changed and how it was tested.
- Include screenshots for meaningful UI changes.
- Request a review from the other developer.
- Do not merge failing or unreviewed work into `main`.

## Code quality
- Use TypeScript in the mobile app.
- Follow Python formatting and typing conventions in the backend.
- Add tests for new backend behavior.
- Never commit secrets or real student personal data.

## Privacy and safety
Treat conversation content, academic records, and personal routines as sensitive. Collect the minimum data needed and obtain clear consent for microphone, camera, and cloud AI processing.
